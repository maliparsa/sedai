# Sedai — Instruction File for Coding Agents

Sedai is a personal Telegram bot backed by Google Gemini. It transcribes voice notes in any language, summarizes messages, drafts replies, and runs plain-text AI chat per user. All configuration is live-updatable without restart.

## Project Layout

sedai/
├── telegram-bot/
│   ├── sedai_bot.py              main event loop, handlers, CHATS/TRANSCRIPTS caches

│   ├── settings_ui.py            /settings menu and admin commands (model/user/key management)
│   ├── style_ui.py               one /<kind>style command per settings.STYLE_KINDS
│   ├── help_ui.py                /help, /start, command menu, unknown-command fallback

## Setup and Health Check

**First-time setup** (interactive, prompts for secrets, writes .env):
```sh
python3 telegram-bot/setup.py
```

**Health check** (non-interactive, verifies existing install):
```sh
python3 telegram-bot/setup.py --check
python3 telegram-bot/setup.py --check --offline   # skip network checks
```

## Tests

**Offline test suites** (no network, no real credentials):
```sh
python3 telegram-bot/tests/run_all.py
```

**Smoke test** (imports real python-telegram-bot, tests command parsing):
```sh
venv/bin/python telegram-bot/smoke_test.py
```

## Non-Obvious Invariants

### Secrets

- `.env` and `settings.json` are mode 0600 and gitignored — never echo or commit them.
- Secrets are only read with `getpass.getpass()`, never as command-line arguments.
- Only display fingerprints: `"…" + value[-4:]`. Never log full tokens or keys.
- `settings.py` writes files atomically: temp file in same directory → chmod 0600 → os.replace(). Match this pattern.

### Logging

Keep `logging.getLogger("httpx").setLevel(logging.WARNING)` — httpx logs full request URLs including the bot token at INFO level.

Never log raw API exception text; log the exception type or status code only. An API error body can echo back request material.

### Message Storage and Privacy

`TRANSCRIPTS` is keyed by `(chat_id, message_id)` tuples, not just `message_id` — Telegram message IDs repeat across chats. Keying by message_id alone was a real cross-user privacy bug here before.

`CHATS` (plain-text chat sessions) is keyed by `chat_id` only, because private chats have `chat_id == user_id`.

### Handler Registration Order

`input_flow.register(app)` must happen before `help_ui.register(app)`. The input-flow handler registers into group -1 so it is seen before text handlers in group 0. Help registers the unknown-command catch-all, which must be LAST so specific handlers run first.

### Admin and User Roles

The first ID in `ALLOWED_USER_ID` is the admin by definition. Code like `settings.admin_id()`, `settings.is_admin(user_id)`, and `settings.is_allowed(user_id)` enforce this.

Refer to users by role only — "admin", "regular user" — never by personal relationship.

### Telegram Library Version

`python-telegram-bot >= 20.x`: `Message.bot` does not exist. Use `context.bot` instead.

### Standing Instructions

The set of standing-instruction kinds is `settings.STYLE_KINDS`. Adding a kind should mean
editing that tuple and nothing else — `style_ui`, the `/settings` instructions screen, and
its callback dispatch all iterate it. Keep it that way; don't reintroduce per-kind branches.

`transcript` is the exception to how a standing instruction is applied. The other kinds go
through `STYLE_SECTION`, which tells the model that a more specific instruction above wins.
Transcription's own prompt demands verbatim output with no commentary, so that precedence
would silently discard any request for timestamps or speaker labels. It uses
`TRANSCRIPT_STYLE_SECTION` instead, where the user's instruction wins. `tests/test_styles.py`
asserts both the precedence wording and that the two sections are not swapped.

### Model Handling

Model names are fetched live from the Gemini API via `settings.available_models()` so deprecated model names are self-service to update — prefer the `-latest` aliases where possible (e.g., `gemini-flash-latest` over `gemini-3.5-flash`).

Fallback chains (audio and text) live in `settings.json` and are updated live; changing them does not require restart.

## Code Style

- Match surrounding code, especially in settings.py and sedai_bot.py.
- Comment the "why", not the "what".
- No new external dependencies — `setup.py` and `telegram-bot/tests/test_setup.py` use standard library only.
- Run `python3 -m py_compile <file.py>` on any changed .py file before shipping.
- Send user-facing bot text as plain text with no `parse_mode`. It carries user-supplied
  instructions and `<key>` / `<id>` placeholders that a Markdown or HTML parser would
  mangle or reject outright.
- Handlers ignore users who fail `settings.is_allowed()` silently — no error reply. Only
  allowed users get the "Unknown command" response.

## Deploy

The repo is designed to be both local-dev friendly and deployable to a server. See `telegram-bot/README.md` for systemd setup. Setup scripts print the commands to run; they never run sudo themselves.
